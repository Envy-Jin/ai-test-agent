# Bug 报告：订单退款模块（2026-09-21 批次）

## BUG-F01 退款接口未校验参数直接受理（严重 · 待修复）
- 环境：Chrome 126 / Windows 11 / 测试环境
- 复现步骤：
  1. 打开订单详情页，点击「申请退款」
  2. 不填订单号（或把订单号改成不存在的 ORD-9999），只填金额 99.5
  3. 点击提交
- 期望：参数缺失返回 400（code=40001）；订单号不属于当前用户返回 401（code=40101）
- 实际：一律返回 200 {"code": 0, "data": {"refund_id": "RF10001"}}，退款单被创建
- 日志：POST /api/refund → 200（校验分支整段未执行）
- 影响：任意用户可对其他人的订单发起退款，资金风险高

## BUG-F02 退款金额可超过订单实付金额（严重 · 待修复）
- 环境：全端 / 测试环境
- 复现步骤：
  1. 对实付 99.5 元的订单发起退款
  2. 金额填 9999.00
  3. 提交
- 期望：拒绝并提示「退款金额不得超过订单实付金额」
- 实际：受理成功，退款单金额 9999.00
- 影响：超额退款，对账不平

## BUG-F03 已取消订单仍可发起退款（一般 · 待修复）
- 环境：全端
- 复现步骤：
  1. 取消一笔已支付订单
  2. 对该订单发起退款申请
- 期望：拒绝并提示「订单状态不支持退款」
- 实际：受理成功
- 影响：产生僵尸退款单，人工审核队列被污染
